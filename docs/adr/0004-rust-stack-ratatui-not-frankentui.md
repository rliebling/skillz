# Rust stack with Ratatui later; not FrankenTUI for v1

skillz is a local CLI with a future TUI, heavy filesystem/VCS integration, and a testable application command API. We implement it in Rust as a binary plus a `skillz-core` library (the test seam), using `clap` for CLI parsing, TOML via `toml`/`toml_edit` for config, and shelling out to `git`/`jj` rather than embedding a VCS library in v1. Interactive `-i` flows will use `ratatui` + `crossterm` when built. We rejected FrankenTUI for v1 despite its richer kernel (inline mode, etc.): its public API is unstable, it expects nightly and path/git consumption, and skillz’s early TUI needs are modest list/multi-select flows. Keep interactive UI behind a thin boundary so a backend swap remains possible later. Elixir/Go/TypeScript were set aside for a single-binary local tool with a first-class Rust TUI path.
