# Replace Skillfile with a narrow owned installer

We need one skill-management tool (including a future TUI) centered on Libraries, Drift Report, and Promote. Wrapping or coexisting with Skillfile would split lock/pin vocabulary and fight that UX. We replace Skillfile in our workflow with a narrow installer (Personal/team/company Library sources, GitHub Upstream, platforms we actually use) rather than pursuing Skillfile parity.

## Considered Options

- Wrap Skillfile for install/lock and build library tooling beside it
- Keep Skillfile for Upstream-only and invent a second path for Owned Entries
- Replace Skillfile with a narrow owned installer (chosen)
