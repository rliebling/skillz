# Tool-Provided skills as Upstream `cmd:` sources

Tool-Provided skills enter a Library only on explicit libcommit, as Upstream catalog references—not Owned file trees—so skillz can re-materialize them through the providing tool instead of a Library mirror. The portable source string is a command template (`cmd:…` with skillz placeholders such as `{dir}`), optionally `|version:…` when `{argv0} --version` is wrong; catalog entries omit `@rev`, while Locks record an observational tool version after a successful probe. On Library add/libcommit, skillz eagerly validates both the install template and the version probe—exercising them the way `github:…` is checked when cataloging—so a bad CLI shape fails before a later Project `add`. Project `add`/refresh always runs the template; missing tools are hard errors. Rejected: a third EntryKind; `tool:provider/skill` identity with opaque adapters as the Lock key; verbatim paths in sources; content-hash pins as the primary Lock rev; Library-vendored fallback copies.
