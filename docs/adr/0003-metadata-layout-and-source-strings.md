# Metadata layout and Upstream source strings

skillz needs a clear split between machine-local state and versioned Project/Library state. Managed Projects keep config and locks under `PROJECT/.skillz/` as `skillz.toml` and `skillz.lock`; Installations live in the configured `skills_dir` (default `.agents/skills`). A user-global registry at `~/.config/skillz/registry.toml` maps Library names to local paths and lists Managed Project paths for Drift without disk-wide scans. User-global skills use `~/.config/skillz/user.toml` / `user.lock` with Installations in `~/.agents/skills`. Libraries store catalog metadata in-repo (e.g. `library.toml`). Upstream identity is a single portable string `github:owner/repo[/path][@rev]` in CLI and TOML—not structured host/repo/path fields—so CLI and files share one grammar (owner/repo are the first two path segments; `@rev` is optional in catalogs and required in locks).
